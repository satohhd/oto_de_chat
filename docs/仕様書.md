# 音通信（oto） 仕様書

テキストメッセージを7音階（ドレミファソラシ）の音に変換してスピーカーから再生し、
マイクで受信してテキストに復元する、音声通信プログラム。

## 1. 概要

- 送信側は文字列を7進数のシンボル列に変換し、シンボルごとに対応する音階（単音）を
  一定時間ずつ鳴らして音声（wav）にする。
- 受信側はその音声をFFT（周波数解析）でシンボル単位に切り出し、各シンボル区間で
  鳴っている音階を判定してテキストに復元する。
- 和音は使わず、常に単音のみを鳴らす設計（`encode.py`内コメントより）。
- ファイル経由（wav→デコード）と、マイクからのリアルタイム受信の両方に対応する。
- 通常モードと、電話回線（帯域300〜3400Hz程度）を想定したモードの2種類がある。

## 2. ファイル構成

| ファイル | 役割 |
|---|---|
| `encode.py` | テキスト→音のエンコード処理一式。定数・エンコード関数・単体実行用CLIを持つ |
| `decode.py` | 音声→テキストのデコード処理一式。FFT解析・同期検出・復号・単体実行用CLIを持つ |
| `chat_speak.py` | 対話的にテキストを入力→即座に音を鳴らす送信側CLI（`chat_out.wav`に書き出して`aplay`で再生） |
| `live_decode.py` | マイク入力を常時監視し、同期音を検出したらリアルタイムに逐次デコードするCLI（`arecord`をストリーミング利用） |
| `record_and_decode.py` | 指定秒数だけ録音→無音トリミング→デコード→確認用に再エンコードまで行うCLI |
| `sample.wav` / `sample_phone.wav` | `encode.py`が生成する動作確認用サンプル音声（通常/電話モード） |

依存ライブラリは `numpy` と標準ライブラリの `wave` のみ。マイク入出力はOSコマンドの
`arecord`/`aplay`（ALSA）をサブプロセスとして呼び出す。

## 3. 通信方式（プロトコル）

### 3.1 文字→シンボルのエンコード

- 音階は7種類（ド〜シ）しかないため、1音を **7進数の1桁（0〜6）** として扱う。
- `7^3 = 343 ≥ 256` なので、**1バイト = 7進数3桁 = 3音** で表現できる（`encode.py:text_to_symbols`）。
- 文字列はUTF-8にエンコードしてからバイト単位で処理するため、日本語等マルチバイト文字も送信できる。
- 復号側（`symbols_to_text`）は3シンボルごとに7進数として組み立てて1バイトに戻し、
  UTF-8としてデコードする。末尾に3の倍数に満たない端数シンボルが残った場合は
  （ノイズ等による誤検出とみなして）切り捨てる。

### 3.2 音声フレームの構成

1つのメッセージは次の順で連結された音声として送出される（`encode.py:encode_to_wav`）。

```
[同期音(プリアンブル)] [無音ギャップ] [データ音1][データ音2]...[データ音N] [末尾無音]
```

| 区間 | 長さ | 内容 |
|---|---|---|
| 同期音 | `SYMBOL_DURATION × SYNC_DURATION_BLOCKS`（既定: 250ms×4=1.0秒） | トニック(ド)の1オクターブ上の周波数を鳴らす。データの7音とは重ならない専用の目印音 |
| 無音ギャップ | `SYNC_GAP`（既定: 50ms） | 同期音直後の残響がデータ音に混ざるのを防ぐための無音 |
| データ音 | シンボル数 × `SYMBOL_DURATION` | 1シンボル=1音（250msが既定）。7進数の各桁に対応する音階を順に鳴らす |
| 末尾無音 | `TAIL_PAD`（既定: 100ms） | 境界検出の誤差でファイル末尾のシンボルが切り捨てられるのを防ぐ余白 |

各トーンは、クリックノイズ防止のため立ち上がり・立ち下がりに `FADE_MS`（既定8ms、
ただし1音の長さの1割を上限に短縮）のフェードをかけて合成する（`encode.py:synth_tone`）。

### 3.3 音階テーブル

| 音名 | ド | レ | ミ | ファ | ソ | ラ | シ |
|---|---|---|---|---|---|---|---|
| シンボル値 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| 通常モード `FREQS`（C5） | 523.26 | 587.32 | 659.26 | 698.46 | 784.00 | 880.00 | 987.76 |
| 電話回線用 `PHONE_FREQS`（C5） | 523.25 | 587.33 | 659.25 | 698.46 | 783.99 | 880.00 | 987.77 |

- 同期音の周波数は `sync_freq_for(freqs) = freqs[0] × 2`（トニックの1オクターブ上）。
  通常モードでは約1046.5Hz。
- 電話回線用は、電話の音声帯域（約300〜3400Hz）に収まるよう設計された専用テーブル。
  現状は通常モードとほぼ同じ音域になっているが、用途上は独立したテーブルとして
  区別されている（帯域制限のある回線を想定する場合は`--phone`を使う）。
- 音階の間隔（Hz差）が広いほど、FFT分解能や周波数ドリフトに対する判定マージンが
  大きくなり誤認識しにくくなる（後述「5.3 速度と誤認識のトレードオフ」参照）。

## 4. 主要パラメータ一覧

| 定数 | 既定値 | 意味 |
|---|---|---|
| `SAMPLE_RATE` | 44100 | 音声のサンプリングレート(Hz) |
| `SYMBOL_DURATION` | 0.25秒 | 1音（1シンボル）の長さ。CLI引数で変更可能（速度調整） |
| `FADE_MS` | 8ms | 各トーンのフェードイン/アウト時間（上限。durationの1割を超えない） |
| `SYNC_DURATION_BLOCKS` | 4 | 同期音の長さ（シンボル何個分か） |
| `SYNC_GAP` | 0.05秒 | 同期音とデータ音の間の無音 |
| `TAIL_PAD` | 0.1秒 | ファイル末尾の余白無音 |
| `SYNC_LOCK_BLOCKS` | 2 | 同期音とロック判定するために連続一致を要求するブロック数 |
| `SYNC_TOLERANCE_RATIO` | 2.9% | 同期音とみなす周波数許容誤差（同期音周波数に対する比率、通常ロック用） |
| `SYNC_TOLERANCE_RATIO_WIDE` | 4.8% | 通常許容誤差でロックできない場合に再試行する緩い許容誤差 |
| `MAX_SYNC_DRIFT` | 8% | これを超える測定ドリフト比は測定ミスとみなし補正を無効化 |
| `HOP_MS`（live_decode） | 10ms | マイクストリームの無音/信号検出の時間分解能 |
| `END_SILENCE_RATIO`（live_decode） | 1.5 | 1音の長さの何倍、無音が続いたらメッセージ終了とみなすか |

## 5. 受信側の処理詳細

### 5.1 同期音の検出（`decode.py:find_sync_start`）

1. 音声先頭付近を10ms刻みで走査し、`SYNC_LOCK_BLOCKS`個連続で同期音周波数と一致する
   位置を探す（まず`SYNC_TOLERANCE_RATIO`、見つからなければ`SYNC_TOLERANCE_RATIO_WIDE`で再試行）。
   実機ではスピーカーの起動遅延で同期音の先頭が欠落することがあるため、
   「決まった長さ一致するか」ではなく「一致し続ける限り読み進め、途切れた瞬間を
   データ開始点とみなす」方式で欠落に強くしている。
2. ロックした同期音ブロックの実測ピーク周波数（放物線補間によりFFTビン幅より
   高精度に推定）と、既知の理論周波数との比から **ドリフト比**（送受信機のクロックの
   ズレによる全体的な周波数シフト量）を推定する。信頼できない値は1.0（補正なし）に
   フォールバックする。
3. 同期音とデータ音の継ぎ目を10ms単位の細かい窓で走査し直し、粗い境界を精密化する。
4. `SYNC_GAP`分を差し引いた位置を、データ音の開始位置として返す。

### 5.2 シンボルの判定（`decode.py:decode_block`）

各ブロック（1シンボル分の音声）に対し、既知の7候補周波数（ドリフト比で補正済み）
それぞれについて直接相関（Goertzelアルゴリズムと数学的に同じ結果を与える
`tone_magnitudes`）を計算し、最も相関の強い候補をそのシンボルの値とする。

これは「FFT全体からピークを1つ探し、候補周波数にnearest-neighborで丸める」という
旧方式（ビン格子への量子化により、候補同士の周波数が近い場合や1音の時間が短い場合に
余計な誤りを生みやすかった）に代わる方式で、量子化なしに各候補の確からしさを
直接評価できるため、同じ条件でも誤認識が少ない。

### 5.3 速度と誤認識のトレードオフ

- FFT/相関による周波数の識別能力は、1音の長さ`duration`が短いほど粗くなる
  （目安: 分解能 Δf ≈ 1/duration）。
- 音階テーブルの中で最も間隔が狭いペア（ミ-ファ）の差がボトルネックになる。
- 上記5.2の相関ベース判定への変更と、音階を高いオクターブに配置して隣接音の
  Hz差を広げることの両方により、同じ1音の長さでもより高速な設定に耐えられるように
  なっている。ただし理論的な限界はduration依存で残るため、無制限に高速化できるわけ
  ではない。

## 6. 各スクリプトの使い方

### 6.1 `encode.py`（単体エンコードCLI）

```
python3 encode.py [1音の長さ(秒)] [出力パス] [--phone]
```
固定メッセージ"HELLO"を音声化する（動作確認・サンプル生成用）。

### 6.2 `decode.py`（単体デコードCLI）

```
python3 decode.py [wavパス] [1音の長さ(秒)] [--phone]
```
既定は`sample.wav`。検出したドリフト比・音階列・シンボル列・復元メッセージを表示する。

### 6.3 `chat_speak.py`（対話送信）

```
python3 chat_speak.py [1音の長さ(秒)] [--phone]
```
標準入力からテキストを読み、`chat_out.wav`に書き出して`aplay`で再生する。
`exit`または空入力（Ctrl+D）で終了。

### 6.4 `live_decode.py`（リアルタイム受信）

```
python3 live_decode.py [1音の長さ(秒)] [--phone]
```
`arecord`でマイク入力をストリーミング取得し、IDLE→BUFFERING(同期音探索)→ACTIVE(復号中)
の状態機械で常時待ち受ける。起動直後の約1.3秒でノイズレベルを較正してから待機に入る。
Ctrl+Cで終了。

### 6.5 `record_and_decode.py`（録音してまとめて復号）

```
python3 record_and_decode.py [録音秒数] [1音の長さ(秒)] [--phone]
```
指定秒数`arecord`で録音（`recorded_mic.wav`）→無音トリミング→同期音検出→復号し、
確認用に復元メッセージを`recorded_reencoded.wav`として再エンコードする。

## 7. 既知の制約

- 誤り検出・誤り訂正符号（チェックサム等）は実装されていない。ノイズ等でシンボルを
  誤判定した場合、そのままメッセージの文字化けとして現れる。
- 同時に複数の音を重ねる「和音」方式には対応していない（設計上あえて単音のみ）。
- マイク/スピーカー入出力はLinuxの`arecord`/`aplay`（ALSA）に依存しており、
  他OSでは別途対応が必要。
- `read_wav`はサンプルレートが`SAMPLE_RATE`(44100Hz)と一致しないwavファイルの読み込みを
  想定しておらず、不一致の場合はエラーになる（`assert`）。
- 通常モードと電話回線モードの周波数テーブルは、現状の設定ではほぼ同じ音域になっている。
